# Product

## Register

product

## Users

Smara Web is for power-user developers and operators who use chat, agents, workflows, tools, and run/status feedback to move fast across development tasks. They work inside a dense app shell, often monitoring long-running agent activity while switching between chat, parallel tasks, and configuration surfaces.

## Product Purpose

Smara Web gives users a controllable interface for running AI-assisted development workflows: normal chat, explicit parallel agent execution, live progress, wave/task status, and actionable results. Success means the user can understand what is running, what wave is active, what needs attention, and what finished without losing context or fighting layout.

## Brand Personality

Capable, sharp, kinetic. The product should feel like an expert operations console for agentic development, not a generic SaaS dashboard. It can be visually bold when showing live agent activity, as long as the interface stays task-first and readable.

## Anti-references

Avoid generic AI SaaS card grids, decorative glassmorphism, oversized hero metrics, vague dashboard chrome, hidden progress, and workflows that start or visually dominate without explicit user intent. Avoid UI that pushes the important run/wave information below the fold.

## Design Principles

1. Make active work visible first: wave and run state should appear before supporting stats.
2. Dense but readable: compact spacing is appropriate for power users, but hierarchy must stay obvious.
3. Explicit control: parallel/workflow behavior should feel user-launched and observable, not automatic or surprising.
4. Bold state, quiet chrome: use stronger visuals for live/active execution states, while keeping navigation and config surfaces restrained.
5. Preserve flow: long-running agent activity should be scannable without excess scrolling or modal interruptions.

## Accessibility & Inclusion

Target accessible product UI fundamentals: readable contrast, visible focus states, semantic buttons/labels, keyboard-friendly controls, motion used only for state feedback, and no reliance on color alone for status.
